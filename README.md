# AutoPatcher для MajorDoMo

Вносит ваши правки в системные файлы и возвращает их, а также нужные модули, после каждого обновления системы.

> **Внимание: этим инструментом можно сломать систему.** Патч меняет системные файлы и применяется автоматически при каждом старте. `php -l` ловит только синтаксические ошибки, но не логические и не несовместимость с текущей версией системы или с другими патчами. Неверный патч может остановить циклы или сделать недоступной панель, и при следующем старте он применится снова. Добавляйте только патчи, в которых уверены, и проверяйте систему после каждого применения.
>
> Восстановление из консоли: перенесите файл патча из `cms/autopatcher/patches/` в другую папку, верните оригиналы из `cms/autopatcher/backup/<дата>_<патч>/` (файлы лежат по своим путям с расширением `.bak`) и перезапустите систему.

## Как работает

При каждом старте `cycle.php` удаляет маркеры `cms/modules_installed/*.installed`, и `control_modules` вызывает `install()` каждого модуля. Это происходит **до** запуска потоков `scripts/cycle_*.php`. AutoPatcher делает свою работу в `install()`:

1. Сравнивает `LatestUpdateId|LatestUpdateTimestamp` с запомненным значением и так узнаёт, что система обновилась.
2. Проверяет каждый патч и применяет те, что ожидают.
3. Ставит модули из списка, если нужно (см. «Модули»). Если модуль что-то установил, патчи проверяются ещё раз: модуль мог перезаписать исправленные файлы.

Патчи идут первыми, чтобы сбой при установке модуля не оставил систему без исправлений. Если установщик модуля завершит процесс (`exit()`, фатальная ошибка), этап сбоя записывается в журнал и в строку «Последний запуск». Модуль получает статус «сбой установки» и дальше ставится только вручную, а патчер снимает свой файл `.error`, чтобы `control_modules` не пропускал его следующий час.

В таблице патчей состояние проверяется по файлам при каждом открытии страницы. Если патчи ожидают, страница подскажет, когда они применятся.

Потоки запускаются уже с исправленными файлами, поэтому при старте системы перезапуск не нужен. Если применить патч вручную из админки или командой `cli.php apply`, модуль запросит перезапуск служб (файл `reboot`). Это можно отключить в настройках.

## Данные: `cms/autopatcher/`

Ни обновление системы, ни обновление самого модуля эту папку не трогают.

| Папка | Что внутри |
|---|---|
| `patches/` | ваши патчи, применяются по возрастанию числа в начале имени (`5-...`, `10-...`, `100-...`); порядок меняется стрелками в списке или полем «Порядок» в карточке |
| `packages/` | локальные архивы модулей `<name>.tgz` |
| `backup/` | оригиналы изменённых файлов (`*.bak`), последние 30 запусков |
| `deleted/` | патчи, удалённые из админки |

## Форматы патчей

**Unified diff** (`*.diff`, `*.patch`), то есть обычный `git diff` или `diff -u`:

```sh
cd /data/data/com.termux/files/home/htdocs
git diff upstream/alpha -- lib/hooks.inc.php > cms/autopatcher/patches/10-hooks-php8.diff
```

Строки `# title: ...` и `# description: ...` в начале файла задают название патча. Можно создавать новые файлы (`--- /dev/null`). Удаление файлов не поддерживается.

**SEARCH/REPLACE** (`*.replace`). Ищется только уникальный якорь, поэтому такой патч переживает изменения в соседних строках:

```
# title: PHP 8: implode() с NULL
FILE: modules/scripts/scripts_edit.inc.php
<<<<<<< SEARCH
точные строки, как сейчас в файле
=======
строки после исправления
>>>>>>> REPLACE
```

В одном файле может быть несколько блоков `FILE:` и `SEARCH/REPLACE`.

Патч можно вставить текстом в админке без имени файла. Имя составится автоматически: следующий номер, строка `# title:` (кириллица транслитерируется) или имя изменяемого файла, расширение по формату. Например: `80-ispravlenie-implode-dlya-php-8.replace`.

## Патч из PR или коммита GitHub

В форме «Добавить патч» вставьте ссылку и оставьте текст пустым. Поддерживаются:

| Ссылка | Что скачивается |
|---|---|
| `github.com/O/R/pull/N` (также `/files`, `/commits`) | `pull/N.diff`: все изменения PR |
| `github.com/O/R/pull/N/commits/SHA`, `github.com/O/R/commit/SHA` | `commit/SHA.diff` |
| `github.com/O/R/compare/A...B` | `compare/A...B.diff` |
| любая ссылка на `.diff` / `.patch` | как есть |

После первой отправки diff открывается в редакторе для проверки, ничего ещё не сохранено. В заголовок патча подставляются:

- `# title:` — название PR или первая строка сообщения коммита (из API GitHub);
- `# source:` — исходная ссылка;
- `# root:` — если указана «Папка назначения». Нужна, когда пути в репозитории не совпадают с корнем MajorDoMo: например, PR в `prasathmani/tinyfilemanager` для модуля `modules/tinyfm`;
- `# exclude:` — автоматически для файлов, которых нет в установке (тесты, документация), служебных папок (`.github` и подобных) и изменений, которые движок не применяет: удаление, переименование, бинарные файлы.

Строки `# exclude:` можно править вручную: путь или маска (`docs/*`), путь берётся как в diff, без `# root:`. Если неподдерживаемое изменение не исключено, патч получает ошибку с объяснением, а не применяется частично.

Если PR уже влит, при загрузке видно `PR: merged`: после обновления системы такой патч станет «применён» сам.

Кнопка «Обновить из источника» в карточке патча скачивает diff заново (PR мог получить новые коммиты). Ваши строки `# exclude:` и `# description:` сохраняются. Если патч применён, а diff изменился, сначала откатите патч: иначе старые правки остались бы в файлах.

## Состояния и гарантии

- **применён**: новый текст уже на месте (применён раньше или исправление влито в upstream);
- **ожидает**: старый текст найден ровно один раз;
- **конфликт**: в обновлении код изменился. **Ничего не записывается**, событие попадает в «Ошибки системы» (один раз, при переходе в это состояние);
- **ошибка**: например, `php -l` нашёл синтаксическую ошибку в результате. Оригинал не тронут.

Патч применяется целиком, по всем файлам, или не применяется вовсе. Сначала пишется временный файл, проверяется через `php -l`, затем атомарно заменяет оригинал. Перед этим делается бэкап. Совпадение ищется только с начала строки, а концы строк CRLF/LF учитываются. Если фрагмент встречается несколько раз, для diff выбирается вхождение на ожидаемой строке, иначе это конфликт. Откат (кнопка «Откатить») применяет патч в обратную сторону и отключает его, чтобы автоприменение не вернуло патч при следующем старте. Чтобы применить снова, включите патч и нажмите «Применить».

Перед откатом проверяется, не правят ли другие применённые патчи те же строки. Так бывает, если один патч — накопительный `git diff`, уже включающий изменения других. Если правят, откат останавливается и показывает список таких патчей. После подтверждения откатываются все вместе: патчер моделирует оба порядка (сначала зависимые или сначала выбранный) и выполняет тот, что не оставляет обрывков; патчи группы отключаются. Если такого порядка нет, файлы не меняются. Чтобы такого не было, делайте патчи без пересечений: один патч на одну правку.

Удаление патча сначала откатывает его. Без вопросов — только если файлы ровно такие, какими их оставил AutoPatcher: после каждого применения запоминаются контрольные суммы изменённых файлов, и когда тот же файл потом меняет другой патч, суммы переносятся. Если файлы изменило что-то другое (обновление системы, модуль) или патч применялся до 1.2.2, патчер спрашивает: «Откатить и удалить» или «Удалить без отката». Так откат не вырежет исправление, которое уже вошло в upstream. Если откат не удался, патч не удаляется. Файл патча переносится в `cms/autopatcher/deleted/`.

## Модули

Для каждого модуля задаются следующие поля. Имя и заголовок можно не заполнять: они берутся из архива (`modules/<имя>/<имя>.class.php` и `$this->title` в нём). Загруженный файл разбирается сразу. Если указана только ссылка, запись сохраняется мгновенно с временным именем из ссылки (`majordomo-tinyfm` → `tinyfm`), а архив скачивается в фоне: событием `AUTOPATCHER_DOWNLOAD` через `processSubscriptionsSafe`, как `HOURLY`. После скачивания имя и заголовок заменяются найденными в архиве. Пока идёт скачивание, список модулей обновляется сам. Если фоновый запрос не завершился за 10 минут, запись получает ошибку и кнопку «Скачать». При старте системы запись с временным именем пропускается.


- имя;
- ссылка на `.tar.gz`: архив GitHub или пусто, тогда ссылка берётся из `plugins.REPOSITORY_URL` Маркета;
- признак установки, по умолчанию `modules/<name>/<name>.class.php`;
- режим:
  - «только если отсутствует»: модуль ставится, только когда нет файла-признака;
  - «переустанавливать, если обновление изменило его файлы»: после каждой установки сохраняются контрольные суммы всех файлов модуля (`packages/<name>.baseline.json`). При каждом старте файлы сверяются с ними, и если хоть один изменён или удалён, модуль переустанавливается. Способ обновления не важен: «Обновление системы», `git pull`, «Обновить всё» в Маркете или ручное копирование. Так же работает `mdm_loaders`. Если модуль был установлен раньше, без сохранённых сумм, при первом старте он один раз переустанавливается, чтобы их получить.

Ход установки виден в трёх местах:
- в таблице «Модули»: дата установки, причина (модуль отсутствовал / файлы модуля изменились / вручную), число файлов и результат последней проверки при старте;
- на странице «Журнал установки»: шаги и список скопированных файлов. Журнал пишется после каждого шага, поэтому при сбое видно, где установка остановилась;
- при старте системы — в консоли `cycle.php` и в `cms/debmes/<дата>/autopatcher.log`.

Если после установки файла-признака нет, модуль получает статус «признак не найден». Иначе он переустанавливался бы при каждом старте.

Модуль ставится из локального архива `packages/<name>.tgz`. Если архива нет, но указана ссылка (или ссылка есть в Маркете), архив скачивается перед установкой. При старте системы скачивание идёт с короткими таймаутами: 5 секунд на соединение, обрыв при скорости ниже 512 байт/с дольше 10 секунд. Так недоступный или зависший сервер не тормозит загрузку. Архивы MajorDoMo Connect (`?op=download`) при старте не скачиваются, их нужно скачать кнопкой. Установка идёт тем же путём, что в Маркете: `market::installUnpacketPlugin()`, импорт скриптов, сцен и классов, `install.php`, список файлов в `cms/modules_installed/<name>.files`.

## Обновления модулей

У каждого модуля есть режим «Обновления»: «Не проверять», «Проверять и сообщать» (по умолчанию) или «Проверять и устанавливать автоматически».

Как определяется версия:

| Ссылка | Версия |
|---|---|
| `github.com/O/R`, `github.com/O/R/tree/ветка`, `…/archive/refs/heads/ветка.tar.gz`, `codeload.github.com/…` | SHA последнего коммита ветки (`api.github.com/repos/O/R/commits/ветка`) |
| `…/archive/refs/tags/тег.tar.gz` | тег последнего релиза (`/releases/latest`) |
| любой другой сервер | заголовок `ETag` или `Last-Modified` |

При скачивании с GitHub архив берётся по конкретному коммиту (`archive/<sha>.tar.gz`), поэтому точно известно, какая версия скачана и установлена. В таблице модулей видны установленная версия, последняя доступная, отметка «Доступно обновление» и кнопка «Обновить».

Проверка запускается на событии `HOURLY` с заданным интервалом (по умолчанию раз в 24 часа) и кнопкой «Проверить обновления». Событие `HOURLY` выполняется фоновым HTTP-запросом (`processSubscriptionsSafe`), поэтому сеть не задерживает ни старт системы, ни циклы. Без токена API GitHub даёт 60 запросов в час с одного IP: один модуль — один запрос за проверку.

Если модуль установлен до появления этой функции, его версия неизвестна (`?`). Первая проверка покажет «Доступно обновление», а после обновления версия станет известна.

## Командная строка

```sh
php /data/data/com.termux/files/home/htdocs/modules/autopatcher/cli.php status   # ничего не меняет
php /data/data/com.termux/files/home/htdocs/modules/autopatcher/cli.php apply
```

Код выхода `1` означает конфликт или ошибку. Это удобно для проверки в `start.sh` или в CI. При вызове через HTTP `cli.php` отдаёт 403.

## Замечания

- Если модуль изменён целиком, проще добавить его в штатную таблицу `ignore_updates`: обновление системы пропустит `modules/<name>` и `templates/<name>`. AutoPatcher нужен для точечных правок, в том числе в `lib/` и корневых файлах.
- `config.php` и сама папка `cms/autopatcher/` патчами не меняются.
- После удаления модуля изменённые файлы остаются как есть. Чтобы вернуть оригиналы, перед удалением откатите патчи.
