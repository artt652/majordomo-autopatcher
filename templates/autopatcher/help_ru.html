AutoPatcher вносит ваши правки в системные файлы и возвращает их, а также нужные модули, после каждого обновления MajorDoMo.

Внимание: этим инструментом можно сломать систему.

Патч меняет системные файлы MajorDoMo и применяется автоматически при каждом старте. Проверка php -l ловит только синтаксические ошибки. Логическую ошибку, несовместимость с текущей версией системы или с другими патчами она не находит. Неверный патч может остановить циклы или сделать недоступной панель управления, и при следующем старте он применится снова.

Добавляйте только патчи, в которых уверены, и проверяйте систему после каждого применения.

Если панель недоступна, восстановите систему из консоли:

  1. перенесите файл патча из cms/autopatcher/patches/ в любую другую папку, чтобы он не применился при следующем старте;
  2. верните оригиналы из cms/autopatcher/backup/<дата>_<патч>/: каждый файл там лежит по своему пути с расширением .bak;
  3. перезапустите систему.

1. Как это работает

При каждом старте cycle.php удаляет маркеры установки модулей, и control_modules вызывает install() каждого модуля. Это происходит до запуска циклов cycle_*.php. AutoPatcher делает свою работу в этот момент:

  1. проверяет все включённые патчи и применяет ожидающие;
  2. ставит модули из своего списка, если их нет или обновление затёрло их файлы;
  3. если модуль что-то установил, ещё раз проверяет патчи.

Циклы стартуют уже с исправленными файлами, поэтому перезапуск при старте не нужен. При старте модуль не ходит в сеть (кроме скачивания отсутствующего архива с короткими таймаутами). Обновления модулей проверяются в фоне по событию HOURLY.

Способ обновления системы не важен: «Обновление системы», git pull, «Обновить всё» в Маркете или ручное копирование. Патчер сравнивает содержимое файлов, а не номер версии.

2. Быстрый старт

  1. Нажмите «Добавить патч».
  2. Вставьте ссылку на PR или коммит GitHub, либо текст патча, либо загрузите файл .diff. Имя файла можно не заполнять.
  3. Нажмите «Отправить». Откроется карточка патча с состоянием по каждому файлу.
  4. Если состояние «ожидает», нажмите «Применить» или дождитесь следующего старта системы.

Для модуля, который нужно держать установленным: «Добавить модуль», вставьте ссылку на репозиторий GitHub и сохраните. Имя модуля определится по архиву.

3. Форматы патчей

Патчи применяются по возрастанию числа в начале имени файла: 5-…, 10-…, 100-…. Порядок меняется стрелками «выше / ниже» в списке или полем «Порядок» в карточке патча. Файл переименовывается сам, а состояние, отключение и сохранённые контрольные суммы остаются с патчем. Если вручную переименовать файл на диске, патч будет считаться новым. Порядок важен, только если патчи правят одни и те же строки: базовый патч должен идти раньше построенного поверх него. Держите один патч на одну правку: так их проще обновлять и откатывать по отдельности.

Unified diff — *.diff, *.patch

Обычный вывод git diff или diff -u, пути от корня MajorDoMo. Например, правка из вашего форка относительно upstream:

cd /data/data/com.termux/files/home/htdocs
git diff upstream/alpha -- lib/hooks.inc.php > cms/autopatcher/patches/10-hooks-php8.diff

Можно создавать новые файлы (--- /dev/null). Удаление, переименование и бинарные файлы не поддерживаются: такие файлы нужно исключить строкой # exclude:.

SEARCH/REPLACE — *.replace

Ищется только уникальный фрагмент, поэтому такой патч переживает изменения в соседних строках:

# title: PHP 8: implode() с NULL
FILE: modules/scripts/scripts_edit.inc.php
<<<<<<< SEARCH
точные строки, как сейчас в файле
=======
строки после исправления
>>>>>>> REPLACE

В одном файле может быть несколько блоков FILE: и SEARCH/REPLACE. Фрагмент должен встречаться в файле ровно один раз и начинаться с начала строки.

Строки заголовка

СтрокаНазначение
# title: …название патча в списке
# description: …пояснение, можно несколько строк
# source: URLоткуда взят патч; включает кнопку «Обновить из источника»
# root: папкадобавляется ко всем путям, если пути в diff идут не от корня MajorDoMo (например, modules/tinyfm)
# exclude: путь или маскапропустить файл (docs/*, .github); путь как в diff, без # root:

Для diff строки заголовка должны стоять до первого diff --git / ---.

4. Патч из PR или коммита GitHub

СсылкаЧто скачивается
github.com/O/R/pull/Nвсе изменения PR
github.com/O/R/commit/SHA, …/pull/N/commits/SHAодин коммит
github.com/O/R/compare/A...Bразница веток
любая ссылка на .diff / .patchкак есть
  1. В форме «Добавить патч» вставьте ссылку, текст оставьте пустым, нажмите «Отправить».
  2. Diff откроется в редакторе. Название подставится из PR или коммита, файлы, которых нет в установке, служебные папки и неподдерживаемые изменения исключатся строками # exclude:. Список исключённого виден над формой.
  3. Проверьте текст и нажмите «Отправить» ещё раз — патч сохранится.

Если PR уже влит (PR: merged), после обновления системы патч станет «применён» сам, и его можно будет отключить.

Кнопка «Обновить из источника» в карточке патча скачивает diff заново: PR мог получить новые коммиты. Ваши строки # exclude: и # description: сохраняются. Если патч применён, а diff изменился, сначала откатите его.

5. Состояния патчей и что делать при конфликте

СостояниеЗначениеЧто делать
применённовый текст уже в файлах: патч применён раньше или исправление вошло в upstreamничего
ожидаетстарый текст найден ровно один раз, патч можно применить«Применить» или дождаться старта системы
конфликтв обновлении код изменился: не найден ни старый, ни новый текст. Файлы не тронуты. В «Ошибках системы» появляется одна записьоткройте карточку патча — там видно, какой файл и фрагмент не сошлись; обновите патч под новый код или отключите, если исправление уже в upstream

Гарантии: патч применяется по всем своим файлам сразу или не применяется вовсе. Новый файл сначала пишется во временный, проверяется php -l и только потом заменяет оригинал. Оригинал перед этим сохраняется в бэкап. Конфликт никогда ничего не записывает.

Состояние в таблице проверяется по файлам при каждом открытии страницы модуля.

6. Откат патча

«Откатить» применяет патч в обратную сторону и отключает его, иначе автоприменение вернуло бы патч при следующем старте. Чтобы вернуть патч, включите его и нажмите «Применить».

Перед откатом патчер проверяет, не правят ли другие применённые патчи те же строки. Так бывает, если один патч построен поверх другого или если патч — накопительный git diff по целому файлу. Тогда откат останавливается и показывает список таких патчей. После подтверждения откатываются все вместе: патчер сам подбирает порядок, при котором не остаётся обрывков, и отключает их. Если такого порядка нет, файлы не меняются.

«Удалить» сначала откатывает применённый патч, затем переносит файл патча в cms/autopatcher/deleted/. Чтобы не вырезать штатный код, патчер откатывает без вопросов, только если файлы ровно такие, какими он их оставил после применения: после каждого применения он запоминает их контрольные суммы. Если файлы с тех пор менялись (обновление системы, установка модуля, патч применён до версии 1.2.2) — например, исправление уже вошло в upstream, — патчер спросит: «Откатить и удалить» или «Удалить без отката». Если откатить не удалось (конфликт), патч не удаляется.

7. Модули: автоустановка и обновления

Добавление

  • Ссылка: репозиторий GitHub (github.com/O/R), ветка (…/tree/ветка), архив (…/archive/…tar.gz) или любой .tar.gz. Если поле пустое, ссылка берётся из Маркета.
  • Или файл: архив .tar.gz.
  • Имя и заголовок можно не заполнять: они берутся из архива (modules/<имя>/<имя>.class.php). Запись сохраняется сразу, архив скачивается в фоне; пока он не скачан, у записи временное имя из ссылки.
  • Признак установки — файл, по отсутствию которого понятно, что модуль нужно ставить. По умолчанию modules/<имя>/<имя>.class.php. Он должен быть в архиве, иначе модуль получит статус «признак не найден».

Когда ставить

  • Только если модуль отсутствует — нет файла-признака.
  • Переустанавливать, если обновление изменило его файлы — после каждой установки запоминаются контрольные суммы файлов модуля; если при старте хоть один изменён или удалён, модуль ставится заново. Для модулей, которые сами перезаписывают файлы ядра.

Установка идёт тем же путём, что в Маркете, из локальной копии архива в cms/autopatcher/packages/. Если копии нет, архив скачивается: при старте системы — с короткими таймаутами (5 с на соединение, обрыв зависшей загрузки через 10 с), архивы MajorDoMo Connect — только кнопкой «Скачать».

Обновления

Режимы: «Не проверять», «Проверять и сообщать» (в строке модуля видно «Доступно обновление» и кнопка «Обновить»), «Проверять и устанавливать автоматически». Проверка идёт по событию HOURLY с интервалом из настроек и по кнопке «Проверить обновления».

Журнал

«Журнал установки» у каждого модуля показывает шаги последней установки и список файлов. Он пишется после каждого шага, поэтому при сбое видно, где установка остановилась. Если установщик модуля аварийно завершил процесс при старте, модуль получает статус «сбой установки» и дальше ставится только вручную.

8. Настройки

  • Применять патчи автоматически — при старте системы. Если выключено, патчи только проверяются.
  • Устанавливать модули автоматически — аналогично для модулей.
  • Перезапускать службы после изменения PHP-файлов — после ручного применения, отката или установки, чтобы циклы подхватили новый код. При старте системы не нужен.
  • Проверять обновления модулей, ч — интервал фоновой проверки.

«Применить всё сейчас» выполняет то же, что при старте, не дожидаясь перезапуска.

9. Командная строка

php /data/data/com.termux/files/home/htdocs/modules/autopatcher/cli.php status   # ничего не меняет
php /data/data/com.termux/files/home/htdocs/modules/autopatcher/cli.php apply

Код выхода 1 — есть конфликты или ошибки. Удобно для проверки в start.sh. При вызове через HTTP cli.php отдаёт 403.

10. Где лежат данные

Всё в cms/autopatcher/. Ни обновление системы, ни обновление самого модуля эту папку не трогают.

patches/ваши патчи
packages/архивы модулей <имя>.tgz, журналы установки, контрольные суммы
backup/оригиналы изменённых файлов (*.bak), последние 30 запусков
deleted/удалённые из списка патчи

config.php и сама папка cms/autopatcher/ патчами не меняются. После удаления модуля изменённые файлы остаются как есть; чтобы вернуть оригиналы, откатите патчи до удаления.

Если модуль изменён целиком, можно использовать штатную таблицу ignore_updates: обновление системы пропустит modules/<имя> и templates/<имя>. AutoPatcher нужен для точечных правок, в том числе в lib/ и корневых файлах.

11. Если что-то не работает

  • Строка «Последний запуск» на главной странице показывает, когда и как шёл последний прогон (boot — при старте системы). Если прогон прервался, там написано, на каком этапе.
  • Журнал: cms/debmes/<дата>/autopatcher.log.
  • Состояние без браузера: cli.php status.
  • Если «Последний запуск» не обновляется после перезапуска, проверьте, что в cycle.php есть блок переустановки модулей: grep -n "Re-installing module" cycle.php.
  • Если модуль переустанавливается при каждом старте, его файл-признак не появляется после установки или модуль сам меняет свои файлы. Исправьте «Признак установки» или выберите режим «Только если модуль отсутствует».
